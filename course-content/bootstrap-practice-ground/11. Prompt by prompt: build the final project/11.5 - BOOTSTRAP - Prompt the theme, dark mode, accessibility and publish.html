Lesson 11.5

Prompt the theme, dark mode, accessibility and publish

How it works

Setting the palette variable is half a theme. Components such as buttons and pagination read their own variables, so they stay Bootstrap blue until you set those too.

Example

Theme the component, not just the palette

Draft

Setting only --bs-primary leaves buttons blue. Buttons read their own component variables.

Prompts for this lesson

Copy each prompt in order. Run one, check the answer against the checklist below it, then move on. Never paste the next prompt until the last one is correct.

1. The theme, naming every target

In css/style.css, below the :root block, add a theme section.

Set --bs-primary and --bs-primary-rgb to the navy #1F3A5F.

Then override the components, because they read their own variables:
.btn-primary: set --bs-btn-bg, --bs-btn-border-color, --bs-btn-hover-bg,
  --bs-btn-hover-border-color, --bs-btn-active-bg and --bs-btn-focus-shadow-rgb.
.btn-warning: the same set, using the gold #C8963E, with dark text for contrast.
.pagination: set --bs-pagination-active-bg and --bs-pagination-active-border-color.
.nav-pills: set --bs-nav-pills-link-active-bg.

Do not use !important anywhere. Do not change any HTML.

Check before you keep it: Look at every page. If any button, link or active pagination number is still Bootstrap blue, a component variable was missed.

2. Dark mode, and the three classes that break it

Add a [data-bs-theme="dark"] block to css/style.css that sets lighter link colours
so they stay readable on a dark background.

Then go through all nine pages and replace:
  bg-light   with bg-body-tertiary
  bg-white   with bg-body
  text-dark  with text-body
These three do not adapt to colour mode and are the usual cause of white boxes
and invisible text in dark mode.

Add a theme toggle button to the navbar with id="themeToggle" and an aria-label.

Check before you keep it: Switch to dark mode and look at every page yourself. No prompt can do this check for you. Look for white boxes, grey on grey text, and any icon that disappears.

3. The accessibility pass

Check all nine pages and report as a list, changing nothing:
1. Every image with missing alt text, or alt text that repeats the filename.
2. Every icon only button or link with no accessible name.
3. Every form field whose label is missing or whose for does not match an id.
4. Every heading level that skips a step.
5. Every place where colour alone carries meaning, with no word or icon beside it.
6. Every id used more than once in the same file.

Check before you keep it: Fix what it finds, then run Lighthouse Accessibility on index.html, admissions.html and admin/index.html. You need 90 or more on all three. Never remove the focus outline to raise a score; restyle it in the brand colour instead.

4. Publish

Create a new public repository on GitHub, push this project to it,
then in Settings, Pages, choose Deploy from a branch, main, / (root).
Wait for the address, then open it on a real phone.

Check before you keep it: Check every image loads on the live site. A file saved as Logo.png and linked as logo.png works on your laptop and fails on the server, because the server is case sensitive.

When should you use this?

Every time you brand a Bootstrap site in its own colours.

Key points

  • Override component variables, never with !important.
  • Replace bg-light, bg-white and text-dark before testing dark mode.
  • Keep a visible focus state; restyle it rather than removing it.

In short

Theme the components, then look at every page in both colour modes yourself.

Try it yourself

Prompt for the theme section, then check that no Bootstrap blue is left on any page in either colour mode.
