Lesson 11.4

Prompt the admin side: sign in, the shell, the dashboard and a list

How it works

Pages in a subfolder need ../ in front of every shared link. It works in the editor either way, and breaks the moment the site is published.

Prompts for this lesson

Copy each prompt in order. Run one, check the answer against the checklist below it, then move on. Never paste the next prompt until the last one is correct.

1. The sign in page, which shares nothing

Build admin/login.html.
This page has no public navbar and no admin sidebar. It shares neither.
Remember it is one folder down, so Bootstrap and css/style.css are linked with ../.

A wrapper with d-flex align-items-center justify-content-center min-vh-100,
with a navy background using the --kr-navy variable through a class in css/style.css.
Inside, a card with a maximum width of 400 pixels set in the stylesheet.

In the card: the school name as an h1 in gold, centred;
a form with needs-validation and novalidate;
form-floating groups for Email address and Password;
a form-check form-switch for "Keep me signed in";
a w-100 btn btn-primary "Sign in";
and a small centred link back to the public site at ../index.html.

Check before you keep it: Load it in the browser. If it is unstyled, the ../ paths are wrong. Check the link back to the public site actually works.

2. The admin shell

In admin/index.html build the admin layout only, with no page content yet.

1. A fixed top bar using the navy brand colour through a class, with a toggler
   button below lg carrying data-bs-toggle="offcanvas" and data-bs-target="#krSidebar",
   an aria-controls attribute and a visually-hidden label;
   the school name in the middle; an account dropdown on the right.

2. A sidebar with id="krSidebar": offcanvas offcanvas-start below lg,
   a fixed column from lg upwards, holding five links in a nav flex-column:
   Dashboard, News, Admissions, Students, Settings. Dashboard is active.

3. A main element with id="krMain", clear of the fixed top bar,
   and beside the sidebar from lg upwards.

Check before you keep it: Check at 360 and at 1280 before you add any content. A shell that is wrong at this point is wrong on four pages by tomorrow.

3. The dashboard content

Inside main#krMain add, in order:

1. A page header with an h1 "Dashboard".
2. Four stat cards in a row row-cols-1 row-cols-sm-2 row-cols-xl-4 g-3:
   Students (300), Applications this term, News posts, Staff.
   Each card has a small muted label and a large number.
3. A card with an h2 "Recent applications" and a table inside table-responsive:
   columns Name, Stream, Date, Status. Status is a badge with the word inside it:
   text-bg-success for Accepted, text-bg-warning for Pending, text-bg-secondary for Draft.
4. A card with an h2 "Latest news posts" and a list-group of three items,
   each with a title, a date and a badge showing Published or Draft.

Check before you keep it: At 360 the stat cards sit one per line and the table scrolls inside its own box.

4. The news list and the news form

Build admin/news-list.html with the shell copied exactly from admin/index.html, News active.
Inside main: a page header with an h1 "News" and a btn btn-primary "New post"
linking to news-form.html; a row with a search input-group and a status form-select;
a card holding a table inside table-responsive with columns
Title, Category, Author, Date, Status and Actions;
icon only Edit and Delete buttons with aria-labels; and pagination.
Every title links to news-form.html.

Then build admin/news-form.html with the same shell, News active.
One needs-validation novalidate form with: Title (text), Slug (text),
Category (select), Publish date (date), Cover image (file input),
Body (textarea rows="10"), and a form-check form-switch for Published.
Every field has a label and an invalid-feedback.
At the bottom, btn btn-primary "Save post" and btn btn-outline-secondary "Cancel".

Check before you keep it: Open all four admin pages in turn. Check every ../ path, check the sidebar active link changes per page, and check the Console on each one, not just the first.

When should you use this?

Any project with an admin folder, a blog folder or any nesting at all.

Key points

  • Check every path from a subfolder before building on it.
  • Copy the shell exactly between admin pages.
  • Check the Console on every admin page, not just the first one.

In short

Paths from a subfolder are the quietest bug in a published site.

Try it yourself

Prompt for the shell on its own, with no page content. Check it at 360 and at 1280 before you build anything on top of it.
