Lesson 10.1

Brief the assistant once, then build the portfolio home page

How it works

An assistant with no house rules drifts. It gives Bootstrap 4 one day and Bootstrap 5 the next, invents class names, and draws a different navbar each time. A short rules file that it reads on every request stops most of that before it starts.

Example

Prompts for this lesson

Copy each prompt in order. Run one, check the answer against the checklist below it, then move on. Never paste the next prompt until the last one is correct.

1. The house rules, saved as .github/copilot-instructions.md

This project uses Bootstrap 5.3 from the jsDelivr CDN only. Never Bootstrap 4.
Use data-bs-* attributes. Never data-toggle or data-target.
Use ms and me for horizontal margins. Never ml or mr.
No jQuery. No inline style attributes. No !important.
Mobile first: write the plain col class first, then add col-md or col-lg.
Every image gets class img-fluid and real alt text that describes the image.
Every icon only button gets an aria-label.
British spelling. No placeholder or lorem text left in any file.
When I ask for a new page, copy the header and footer from index.html exactly
and change only which link carries the active class.

Check before you keep it: Open the file and read it back. This is the one file you write by hand, because everything after it depends on being right.

2. Scaffold only, no content

Create index.html for a personal portfolio site.
Include only: the doctype, html with lang="en", a head containing charset,
the viewport meta, a title, the Bootstrap 5.3 CSS link from jsDelivr, and a body
containing nothing but the Bootstrap bundle script tag before the closing body tag.
Do not add any page content, navbar, hero or footer yet.

Check before you keep it: The version number in both CDN URLs reads 5.3 something. If it says 4, stop and ask again naming the version.

3. The page, in four named parts

In index.html, build four sections in this order. Use only Bootstrap 5.3 classes.

1. Navbar: classes navbar navbar-expand-lg bg-body-tertiary sticky-top.
   Brand text "Amina Yusuf". Links: Home, About, Work, Contact.
   It collapses behind a navbar-toggler below the lg breakpoint.
   Home carries class active and aria-current="page".

2. Hero: a container with py-5. One h1, one paragraph with class lead,
   then two buttons, btn btn-primary "See my work" and btn btn-outline-secondary "Contact me".

3. "What I do": a row with classes row-cols-1 row-cols-md-3 g-4.
   Three cards of equal height, each with a Bootstrap Icon, an h3 and two lines of text.

4. Footer: bg-body-tertiary py-4, centred text, with the year inside a span with id="year".

No inline styles. No invented class names.

Check before you keep it: Count the sections. Read every class you do not recognise and look it up. Open the device toolbar at 360 pixels and check the three cards sit one per line with no sideways scrolling. Look at the Console.

When should you use this?

Write the rules file first, before any HTML, every time you start a project with an assistant.

Key points

  • Name the exact version in the rules file.
  • Ask for one page in named parts, not a whole site.
  • Check version, class names, 360 pixels and the Console before you keep anything.

In short

Set the rules once, then ask for small pieces you can actually check.

Try it yourself

Inspect both paragraphs in DevTools. Check which class has a matching CSS rule, then verify the real class in the Bootstrap docs.
