Lesson 10.5

Prompt the dashboard, the list, the detail page and the admin form

How it works

A dashboard is four or five small, familiar pieces arranged on a shell you already checked. Asking for all of it at once gives you one page you cannot verify.

Prompts for this lesson

Copy each prompt in order. Run one, check the answer against the checklist below it, then move on. Never paste the next prompt until the last one is correct.

1. The dashboard, in four named parts

Inside main#adminMain in index.html, add these parts in order.

1. A page header: d-flex justify-content-between align-items-center mb-4,
   with an h1 "Dashboard" on the left and a btn btn-primary with a plus icon
   and the text "Add product" on the right.

2. Four stat cards: a row with row-cols-1 row-cols-sm-2 row-cols-xl-4 g-3.
   Each card body holds a small muted label, a large number, and one line
   of change text using text-success or text-danger.
   Use Products, Orders this week, Low stock and Customers.

3. Recent orders: a card containing an h2 and a table inside table-responsive.
   Columns: Order, Customer, Date, Total, Status.
   The Status column uses badge text-bg-success, text-bg-warning or text-bg-secondary,
   with the status word written inside the badge.

4. Low stock: a card containing an h2 and a list-group,
   each row showing a product name and a badge with the number left.

Check before you keep it: At 360 the four stat cards sit one per line. The status words are readable without relying on colour. The table scrolls inside its own box rather than pushing the page sideways.

2. The list page

Build products.html.
Copy the entire shell from index.html exactly: the top bar, the sidebar and main#adminMain.
Set the active sidebar link to Products.

Inside main add:
1. A page header with an h1 "Products" and a btn btn-primary "Add product"
   linking to product-form.html.
2. A row with g-2: an input-group holding a search icon and a search input in
   col-12 col-md-6, and a form-select for category in col-12 col-md-3.
3. A card holding a table inside table-responsive, with columns
   Photo, Name, Category, Price, Stock, Status and Actions.
   Photo is a small square image with alt text. Name is a link to product-detail.html.
   Status is a badge with the word inside it.
   Actions holds two icon only buttons with aria-label "Edit product" and "Delete product".
4. Pagination underneath, inside a nav with an aria-label.

Check before you keep it: Every product name is a real link. Both icon buttons have an aria-label. The table does not push the page sideways at 360.

3. The detail page

Build product-detail.html with the same shell copied exactly, Products active.

Inside main:
1. A breadcrumb nav: Products, then the product name as the current page.
2. A row with g-4: col-12 col-lg-5 holding the product photo with img-fluid rounded,
   and col-12 col-lg-7 holding the details.
3. The details as a description list: dl with dt and dd pairs for
   Category, Price, Stock, Supplier and Last updated, plus a status badge.
4. Two buttons at the bottom: btn btn-primary "Edit" linking to product-form.html,
   and btn btn-outline-secondary "Back to products" linking to products.html.

Check before you keep it: The breadcrumb and the Back button both work. At 360 the photo sits above the details.

4. The admin form

Build product-form.html with the same shell copied exactly, Products active.

Inside main, one form with needs-validation and novalidate, split into three cards:

Card 1, Details: Product name (text), Category (select), Description (textarea rows="4").
Card 2, Pricing and stock: Price inside an input-group with a dollar sign prefix,
Stock as a number input with min="0", and a form-check form-switch for "Published".
Card 3, Photo: a form-control file input that accepts images only.

Every field has a label with a for matching its input id, and an invalid-feedback
div with a sentence saying what to fix.

At the bottom, outside the cards, a d-flex gap-2 holding
btn btn-primary "Save product" and btn btn-outline-secondary "Cancel"
linking back to products.html.

Check before you keep it: Submit the empty form. Every required field shows its own message. Then run the review prompt from lesson 50 across the whole admin folder.

When should you use this?

Any admin screen: a dashboard, a list, a detail page or a form.

Key points

  • Build on a shell that already works at 360 and 1280.
  • Ask for one page at a time and link them yourself.
  • Put the status word inside the badge; colour alone is not a status.

In short

Prompt page by page on a checked shell, and say out loud that the result is layout only.

Try it yourself

Prompt for these four parts one at a time. Check that the status word is inside the badge, not carried by the colour alone.
