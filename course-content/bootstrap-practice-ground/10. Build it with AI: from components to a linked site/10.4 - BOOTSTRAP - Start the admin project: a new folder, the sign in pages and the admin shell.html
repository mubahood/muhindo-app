Lesson 10.4

Start the admin project: a new folder, the sign in pages and the admin shell

How it works

Layouts belong to states. A signed out page, a signed in page and a public page are three different shells, and an assistant will merge them unless you say so.

Example

A sign in card with nothing else on the page

Prompts for this lesson

Copy each prompt in order. Run one, check the answer against the checklist below it, then move on. Never paste the next prompt until the last one is correct.

1. The admin rules file, saved as admin-demo/.github/copilot-instructions.md

This is the admin area of a small shop. Bootstrap 5.3 from the jsDelivr CDN only.
All the general rules from the public site apply: data-bs-*, ms and me, no jQuery,
no inline styles, mobile first, img-fluid, alt text, aria-labels on icon only buttons.

Rules that are specific to this folder:
There is no public navbar anywhere in this project.
Signed in pages share one shell: a fixed dark top bar, a sidebar, and a main content area.
login.html and register.html share neither the shell nor a navbar. They are
centred cards on an otherwise empty page.
Every table is wrapped in table-responsive.
Every status is shown as a badge with the status word written inside it, never colour alone.

Check before you keep it: The three rules about layout are the ones that save the most time. Without them the assistant puts a sidebar on the sign in page.

2. The file tree first, nothing else

Create these files for a small admin area and leave them empty apart from the page shell:
index.html (the dashboard), login.html, register.html, products.html,
product-detail.html, product-form.html, and css/admin.css.

Every HTML file links the Bootstrap 5.3 CSS from jsDelivr first, then css/admin.css,
and loads the Bootstrap bundle script before the closing body tag.
Write no page content at all yet.

Check before you keep it: Open one file and confirm admin.css is linked after Bootstrap, not before, or your own rules will be overridden.

3. The sign in page

Build login.html.
Do not add a navbar. Do not add a sidebar. This page has neither.

Structure: a wrapper with d-flex align-items-center justify-content-center min-vh-100
and bg-body-tertiary. Inside it a card with class shadow-sm and a maximum width of
420 pixels set in css/admin.css, not inline.

Inside the card body:
an h1 with the shop name, centred, in a smaller display size;
a form with needs-validation and novalidate;
two form-floating groups, Email address and Password, each with a matching label and id;
a form-check form-switch for "Remember me";
a submit button with classes btn btn-primary w-100;
a small centred line underneath reading "No account yet?" with a link to register.html.

Check before you keep it: No navbar, no sidebar. The card stays readable at 360 pixels and does not touch the screen edges.

4. Register by copying, not by inventing

Create register.html by copying login.html exactly.
Change only three things: the heading, the fields, and the bottom link.
Fields: Full name, Email address, Password, Confirm password, each as a form-floating group.
The bottom line now reads "Already have an account?" and links to login.html.
Keep the same wrapper, the same card, the same classes and the same button.

Check before you keep it: The two pages should look like the same page. If the card width or spacing changed, ask again and say copy exactly.

5. The shell every signed in page shares

In index.html build the admin layout only. Add no page content yet.

1. A fixed top bar: nav with classes navbar navbar-dark bg-dark fixed-top.
   On the left, below lg only, a button that opens the sidebar: it needs
   data-bs-toggle="offcanvas", data-bs-target="#adminSidebar", an aria-controls
   attribute and a visually-hidden label.
   In the middle the shop name. On the right a dropdown for the signed in user.

2. A sidebar with id="adminSidebar": classes offcanvas offcanvas-start below lg,
   and a fixed column from lg upwards. It holds five nav links in a nav flex-column:
   Dashboard, Products, Orders, Customers, Settings. Dashboard is active.

3. A main element with id="adminMain" for page content, offset so it is not hidden
   behind the fixed top bar, and sitting beside the sidebar from lg upwards.

Check before you keep it: Two states to test. At 360 the sidebar is hidden and the button opens it as a panel. At 1280 the sidebar is always visible and the content sits beside it, not underneath it.

When should you use this?

Whenever a project has both a public side and an area behind a sign in.

Key points

  • Give the admin project its own rules file.
  • Ask for the file tree before any content.
  • Say plainly which pages get no navbar and no sidebar.

In short

Tell the assistant which pages share which layout, or it will guess and guess wrongly.

Try it yourself

Build this page by prompting, then check the one thing a prompt gets wrong most often: no navbar and no sidebar on a sign in page.
