How it works

A review prompt works when you give it the list to check against. Asking an assistant whether your code is good invites it to agree with you.

Prompts for this lesson

Copy each prompt in order. Run one, check the answer against the checklist below it, then move on. Never paste the next prompt until the last one is correct.

1. The contact page

Create contact.html. Copy the navbar and footer from index.html exactly,
and set the active link to Contact.

Between them add a container py-5 holding a row with g-4:

Left column col-12 col-lg-7: a form with class needs-validation and the novalidate attribute.
Fields: Full name (text), Email address (email), Subject (a select with four options),
and Message (a textarea with rows="5"). Every field is required, has a label with a for
attribute matching the input id, and is followed by a div with class invalid-feedback
containing a helpful sentence that says what to do, not just "invalid".
Submit button: btn btn-primary.

Right column col-12 col-lg-5: a card with an h2, then address, phone and email,
each line beginning with a Bootstrap Icon marked aria-hidden="true".

Check before you keep it: Click submit with the form empty. Every field should show its own message. Tab through the whole form with the keyboard and watch for a visible focus ring at every stop.

2. The review prompt. Give it the list, never ask for an opinion.

Review index.html, about.html and contact.html together as one website.
Report your findings as a numbered list and change nothing.

Report each of these separately:
1. Any class that is not part of Bootstrap 5.3, with the file and line.
2. Any spacing utility value that does not match the pattern used on the other pages.
3. Any heading level that skips a step, for example an h2 followed by an h4.
4. Any image with missing alt text, or alt text that is just the filename.
5. Any id that appears more than once in the same file.
6. Any link whose target file does not exist in this folder.
7. Any difference between the three navbars other than the active link.

Do not rewrite the files. Do not suggest redesigns. Only report.

Check before you keep it: Read the list yourself and decide what to act on. A report is not a to do list; some of what it finds will be wrong.

When should you use this?

At the end of any set of pages, before you call the work finished.

Key points

  • Give the checklist; do not ask for an opinion.
  • Tell it to report and change nothing, so you stay the one deciding.
  • Run Lighthouse on the page with the form, not only the home page.

In short

A good review prompt asks for a list of specific problems, not for praise.
