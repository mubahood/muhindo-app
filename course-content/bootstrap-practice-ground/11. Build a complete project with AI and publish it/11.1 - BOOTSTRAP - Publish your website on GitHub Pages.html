Lesson 11.1

Publish your website on GitHub Pages

How it works

A site on your laptop is a site nobody can see. GitHub Pages takes a folder of HTML, CSS and images and serves it on a real web address, free, with no server to rent and nothing to configure.

You push the folder to a repository, switch Pages on in the settings, wait a minute, and you have a link you can put on your CV and send on WhatsApp.

Example

From a folder on your laptop to a live address

What you push

The project folder itself, with index.html at the top level beside css/ and images/.

What you get back

An address shaped like https://yourname.github.io/your-repo/ that updates every time you push.

Code for this example

The folder you publish

my-site/
  index.html        <-- must be called index.html
  about.html
  contact.html
  css/
    style.css
  images/
    hero.jpg
  admin/
    index.html

Pushing it the first time

cd my-site
git init
git add .
git commit -m "First version of the site"
git branch -M main
git remote add origin https://github.com/yourname/my-site.git
git push -u origin main

Then, in the repository on github.com

Settings  >  Pages
  Source: Deploy from a branch
  Branch: main    Folder: / (root)
  Save

Wait about a minute, then reload. The live link appears at the top.

Pushing a change later

git add .
git commit -m "Fix the footer link"
git push

When should you use this?

For any site that is only HTML, CSS, images and JavaScript. Anything needing PHP or a database needs real hosting instead, which is a later course.

Key points

  • The home page must be named index.html, in lower case, at the root of what you publish.
  • Use relative paths. css/style.css works; /css/style.css and C:\Users\... both break once published.
  • From a subfolder you must go up first: ../css/style.css. This is the single most common broken-stylesheet cause.
  • GitHub is case sensitive. Hero.JPG on your Mac becomes a missing image on Pages if the HTML says hero.jpg.
  • The first build takes a minute or two. A 404 straight after saving usually just means it has not finished.
  • Every push republishes. There is no separate deploy step.

In short

Push the folder, switch Pages on, and your work has an address that anyone in the world can open.

Try it yourself

Publish the site you built in the previous lesson. Then open the live address on your phone, not your laptop, and walk every page. Write down anything that is broken on Pages but worked locally, and fix the paths until nothing is. Keep the live link; you will submit it with the final project.
