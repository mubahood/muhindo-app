Lesson 11.0

Prompt an AI agent to build a complete website

How it works

You have spent nine modules learning what every class is called. Now you stop typing them one at a time. You describe a whole site in one brief, hand it to an assistant, tell it to use Bootstrap 5.3 and to write its own CSS for anything Bootstrap does not cover, and then you do the job that is actually yours: reviewing what comes back.

This is how the work is done now. The assistant is fast and tireless and confidently wrong. You are the one who knows the difference, and your name goes on the result.

Example

One brief, then house rules, then review

Pick any site you have never built: a clinic, a church, a garage, a school, a salon. Write the brief once, in plain words, and say what the site is for and who reads it. Let the assistant choose the pages and the content.

1. The brief

What the site is, who it is for, roughly how many pages. One paragraph, not a specification.

2. The house rules

Bootstrap 5.3 from the CDN, its own CSS file for the rest, no inline styles, mobile first, real alt text.

3. The review

Open it at 360, 768 and 1280. Tab through it. Check the links. Send back one list of fixes.

Code for this example

The brief you type

Build a complete website for a small veterinary clinic in Kampala.
Decide the pages yourself, write real content, no lorem text.

House rules:
- Bootstrap 5.3 from the jsDelivr CDN only, never Bootstrap 4.
- Write your own css/style.css for anything Bootstrap does not cover.
- No inline style attributes and no !important.
- Mobile first: plain col first, then col-md and col-lg.
- Every image gets img-fluid and alt text that describes the image.
- Every icon only button gets an aria-label.
- One header and one footer shared by every page, with the
  active link changing per page.

Build it, then tell me which files you created and why.

The review you run before you accept anything

1. Does every page open? Any link that goes nowhere?
2. Resize to 360, 768, 1280. Does anything overflow sideways?
3. Tab through with the keyboard only. Can you reach every control?
4. Is it Bootstrap 5 markup? data-bs-*, ms and me, never ml or mr.
5. Any lorem text, any empty alt, any inline style left behind?
6. Dark mode: does the page still read?

The finished project

Marigold Shop, the site you build by hand across this course, is live at https://mubahood.github.io/marigold-shop/ with its source at https://github.com/mubahood/marigold-shop. An AI built example and the practice pages are at https://mubahood.github.io/bootstrap-practice/. Compare the shape of the work, not the content: yours will be a different shop.

When should you use this?

On any project where the shape is ordinary and the content is yours: a brochure site, a portfolio, an admin area, a landing page. Direct it, review it, ship it.

Key points

  • One clear brief beats twenty small prompts that each repeat half of the last one.
  • Say the Bootstrap version out loud. Assistants reach for Bootstrap 4 habits unless you stop them.
  • Ask for a separate CSS file, not inline styles, so the work stays reviewable.
  • Review at three widths and with the keyboard before you accept anything.
  • Send fixes back as one list, not one message per problem.

In short

You describe the outcome, the assistant types, and you decide what is good enough to carry your name.

Try it yourself

Choose a business you have never built a site for. Write one brief and one set of house rules, hand both to your assistant, and let it build the whole site. Then run the six review checks above and send back a single list of fixes. Keep the brief, the rules and your fix list; you will submit them with the final project.
